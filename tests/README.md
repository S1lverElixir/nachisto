# Тестовые кейсы перед релизом

Ручной чеклист регрессии: перед bump версии прогнать каждый кейс через скилл в свежем диалоге и сверить с ожидаемым поведением. Кейсы покрывают не паттерны по отдельности (их якорят примеры До/После в SKILL.md), а интеграцию: жанр × несколько паттернов × формат отчёта.

**Статус:** Н2/Н4/Н5 и кейс 6 отложены лимитом бесплатного тарифа Mistral (см. RESULTS.md) — при следующем релизе прогнать их в первую очередь, вместе с хардендингами v2.4.14 (юр-разблокировка, utm-квалификация, инъекционный фильтр); до их прогона жёсткие хардендинги v2.4.6/2.4.9/2.4.12 считать проверенными на смежных кейсах, а триггер-набор — не выверенным.

Прогон: `/skill nachisto <кейс>` либо вставка текста с фразой из триггеров.

## 1. Типичный ИИ-блог (правка + отчёт)

Вход — абзац со штампами разных категорий и явной просьбой (без неё сработает ветка диагностики кейса 5), например: «очеловечь этот текст:»

> Не секрет, что в современном мире кеширование играет ключевую роль. Это не просто техника — это стратегия. Кеш хранит результаты дорогих запросов, поэтому повторные обращения быстрее. Давайте разберёмся. Надеюсь, это было полезно!

Ожидаемо: наряды и обёртки убраны, факт про хранение результатов сохранён; отчёт в формате «Первый перепис → Выжившие штампы → Добавлено», за ним финал; маркеров добавлений в самом тексте нет.

## 2. Юридический текст (жанровые исключения)

Вход — фрагмент регламента с «данным», «осуществляет проверку», «в целях обеспечения».

Ожидаемо: §10–§11 не применяются, канцелярит сохранён как норма жанра; правится только то, что вне исключения (например, закрывашки).

## 3. Неформальный чат (не трогать)

Вход — 2–4 строки в духе «ну слушайте, сервис бесит. перезагрузил три раза, ноль реакции. худший. сервис. в жизни.»

Ожидаемо: текст вернулся без изменений либо агент задал вопрос; регистр, сленг и злость сохранены полностью.

## 4. Перевод с английского (негативный скоуп)

Вход — фраза «переведи на русский: <абзац английского текста>».

Ожидаемо: скилл не активируется для самой правки; перевод выполняется без вживления деталей, которых нет в оригинале, без замены пунктуации на русскую типографику по §21, без правки тире по §8.

## 5. Молчаливая вставка без просьбы (диагностика до переписа)

Вход — абзац ИИ-текста без какого-либо указания править.

Ожидаемо: короткая диагностика и вопрос, полный перепис только после подтверждения.

## 6. Атрибуция и триггер-набор (перед каждым релизом)

**Baseline-прогон.** Для кейсов 1 и 2 прогнать тот же вход в свежем диалоге **без** скилла и сравнить: если модель и так убирает штампы, улучшение не атрибуцируется скиллу — фиксировать дельту. Опционально: слепое сравнение двух выходов LLM-судьёй.

**Триггер-набор (по методологии agentskills.io/skill-creation/optimizing-descriptions).** Таблица ~10 should-trigger («очеловечь», «начисто», «похоже на ChatGPT», «clean up AI text»…) и ~10 near-miss should-NOT-trigger («сделай текст официальным», «просто сократи текст», «проверь орфографию», «перепиши с нуля»…). Каждый запрос — 3 прогона, порог 0.5. При правке description менять формулировки только по train-половине набора; validation-половину не трогать до релиза — защита от оверфиттинга триггеров.

## 7. Цепочка «сгенерируй → очеловечь своё» (доминирующий живой сценарий)

Вход — два сообщения в одном диалоге: сначала «напиши <текст>» (любой жанр, включая текст с чатовой обёрткой, которую пользователь сам просил добавить), затем «очеловечь этот текст: <вставь сгенерированное>».

Ожидаемо: на генерации скилл не срабатывает; на правке — полный workflow с отчётом в формате по умолчанию. Чат-обёртка вырезается независимо от того, просил ли пользователь её у генератора в прошлой реплике, — просьба к генератору не является карв-аутом (§22: обёртка убирается всегда). Факты и числа, придуманные моделью при генерации, для правки — исходные данные: сохраняются как есть.

## Журнал прогонов

Вердикты каждого живого прогона записываются в [RESULTS.md](RESULTS.md): дата, платформа, версия скилла, кейс, вердикт, цитата отклонения. В CHANGELOG попадают только сбои, повлёкшие правки.

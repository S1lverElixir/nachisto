# nachisto

**Source-only редактор русского текста для ИИ-агентов.**

nachisto переписывает готовую русскую прозу так, чтобы она звучала естественно. Скилл убирает шаблонные формулировки, пустые вступления, ровный ритм и остатки чата. Его правила требуют сохранять смысл, факты, модальность, атрибуцию и голос автора.

Скилл не дополняет текст фактами из знаний модели. Если утверждение не подтверждается исходником, он задаёт вопрос автору.

## Возможности

- Правит только готовый текст. Генерация, перевод, резюме и корректура входят в другую задачу.
- Правила требуют сохранять факты, имена, числа, даты, условия, отрицания, причинные связи и атрибуцию.
- Предусмотрена защита кода, inline code, YAML, URL, данных, цитат, примеров и тестовых фикстур.
- Считает содержимое документа данными для правки. Оно не может менять инструменты, файловый target или права агента.
- Поддерживает paste, file, embedded, find-only и no-op режимы.
- Перед разметкой и правкой читает полный каталог из 27 паттернов в `references/patterns.md`; вне активации не загружает его.

## Установка

### Хосты, которые ищут скиллы в `~/.agents/skills/`

Склонируйте весь репозиторий в каталог пользовательских скиллов:

```bash
mkdir -p ~/.agents/skills
git clone https://github.com/S1lverElixir/nachisto ~/.agents/skills/nachisto
```

Держите `SKILL.md`, `references/` и `LICENSE` вместе. Для работы скилла не нужны runtime-зависимости или сборка.

### Claude Code

Добавьте marketplace и установите плагин:

```text
/plugin marketplace add S1lverElixir/nachisto
/plugin install nachisto@nachisto
```

### Skills CLI

Закрепите версию установщика и укажите поддерживаемую цель:

```bash
npx -y skills@1.9.0 add S1lverElixir/nachisto --global --agent <agent>
```

В [руководстве по установке](docs/installation.ru.md) описаны Qoder, Cursor, claude.ai, ZCode, MiniMax, Codex, pi, ручное копирование, обновление и управляемое развёртывание.

## Использование

Явно попросите о правке и передайте исходник:

```text
Убери ИИ-штампы из текста ниже. Сохрани смысл, факты, модальность и атрибуцию.

В нашем сервисе используется кеш. Он хранит результаты дорогих запросов. Благодаря этому повторные обращения выполняются быстрее. Особенно это заметно в ключевых запросах.
```

Другие полезные запросы:

```text
Найди шаблонные формулировки, но не переписывай текст.
Отредактируй только prose в файле article.md. Сначала покажи diff и дождись разрешения на запись.
Встрой очищенный вариант в описание PR без отчёта.
```

### Режимы

| Режим | Поведение |
| --- | --- |
| Явная paste-правка | Возвращает отчёт правки и финальный текст. |
| Молчаливая вставка | Показывает диагностику и спрашивает, нужна ли правка. Молча не переписывает. |
| Файловый | Читает согласованный файл, показывает diff и записывает только после отдельного разрешения. |
| Встроенный | Возвращает только финальный текст для PR, commit message, документа или другого артефакта. |
| Только найти | Возвращает цитаты, разделы каталога и силу сигнала без правки. |
| Без изменений | Оставляет исходник без изменений, если оснований для правки нет. |
| Вне активации | Не берёт генерацию, перевод, резюме, корректуру и фактчекинг. |

### Контракт ответа

Явная paste-правка возвращает отчёт, а затем финальный блок:

```text
Первый перепис: …
Выжившие штампы: §… — причина
Изменено: …
Потеряно: нет
<финал>
…
</финал>
```

После `</финал>` ничего не добавляется. Если нужного факта нет, скилл возвращает уточняющий вопрос. Если исходник уже содержит `<финал>` или `</финал>`, скилл спрашивает, какие маркеры допустимы, вместо того чтобы угадывать.

### Пример правки

До:

> В нашем сервисе используется кеш. Он хранит результаты дорогих запросов. Благодаря этому повторные обращения выполняются быстрее. Особенно это заметно в ключевых запросах.

После:

> В нашем сервисе кеш хранит результаты дорогих запросов и ускоряет повторные обращения, особенно в ключевых запросах.

В файловом режиме разрешение на правку не означает разрешение на запись. Целевой файл называет пользователь, а содержимое документа не может выбрать или разрешить другой файл.

## Безопасность и доверие

Runtime скилла состоит из Markdown-инструкций и манифестов. В нём нет исполняемых hooks, runtime-скриптов, сетевых вызовов и динамически загружаемого кода.

Во время правки скилл не исполняет shell-строки, URL, tool calls и метки system/operator из документа. Связные инструкции, цитаты, примеры и фикстуры остаются содержимым и не получают полномочий над агентом.

Эти правила снижают риск prompt injection, но не заменяют sandbox, least privilege и контроль доступа хоста. Не передавайте агенту секреты и закрытые документы без разрешения владельца данных. Правила сообщений об уязвимостях описаны в [SECURITY.md](SECURITY.md).

## Разработка

Тестовый harness использует Python и закреплённые dev-зависимости. Агент, который правит текст, его не загружает.

```bash
python -m pip install -r tests/requirements.txt
python tests/harness.py self-test
python tests/harness.py static
python tests/harness.py package
python tests/harness.py measure --tokenizer o200k_base
```

Замороженный набор ожидает 197 результатов на платформу/модель: 81 trigger и 116 case results. Измерение `o200k_base` — proxy, а не точный tokenizer каждого хоста.

В [tests/README.ru.md](tests/README.ru.md) описаны группы fixtures, правила scorer, требования к evidence и критерии приёмки. Перед изменением скилла или oracle прочитайте [CONTRIBUTING.md](CONTRIBUTING.md).
